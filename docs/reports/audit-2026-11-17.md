## Finding 4 — re-scoped: prefer the provider's own cost

**Status: in progress in the working tree, not committed.** The shape taken:

- `UsageCollector.setProviderCost()` seeds `state.usage.providerCostUsd`;
  `handleEnd` uses `providerCostUsd ?? estimateCostUSD(...)`, so the provider's
  number reaches both the row and the per-API-key spend counter.
- `recordProviderCost()` mirrors `recordDiscoveredProviderServed`: seed the
  collector, fall back to a `COALESCE` row update when the collector has
  already finalised the request.
- `response-processor.ts` reads `anthropic-billing-cost` in both branches and
  takes `usageInfo.costUsd` (OpenRouter body `usage.cost`) in the non-streaming
  branch.
- `openai/provider.ts` drops the hard-coded price table and reports
  `usage.cost` when the provider states one.

Still open before this is done:

- `response-processor-provider-cost.test.ts` fails 3 of 5. The header cost is
  found and `recordProviderCost` is called, but `setProviderCost` returns
  false: the test's `collector` is not the one the handler reaches through
  `tryGetUsageCollector()`. The fallback UPDATE then runs against a row that
  `handleEnd` has not inserted yet, so `rowCost()` reads null. Fix the harness,
  not the production code.
- Debug scaffolding is still in that test file: `console.log` lines, a
  prototype patch of `setProviderCost`, and a "DBG identity" test.
- Two stray/duplicated doc blocks left by the edit: `response-processor.ts`
  ~line 409 and `usage-collector.ts` ~line 1597.
- The provider cost is not gated on the cost-tracking epoch. The collector's
  `providerCostUsd` bypasses the `isCostTrackingEnabled()` branch, so a
  provider cost recorded while tracking is off would still be written.
- OpenRouter streaming reports `usage.cost` only on the final SSE frame;
  `OpenAICompatibleProvider.extractUsageInfo` returns null for SSE, so that
  path is not wired.
- Two failures look pre-existing rather than caused by this change: one test
  times out in `usage-collector-provider-served-collector.test.ts`, and
  "provider metadata cost writes across a tracking gap > JSON: omits stale
  cost after-enqueue" fails. Confirm against a clean `main` before fixing.

### Background

The original finding was "the OpenAI-compatible `calculateCost` table is dead
code". The user's decision is broader: **when a provider tells us the cost, use
it; only estimate when it does not.**

### What happens today

1. The provider parses usage and may set `costUsd`:
   - `providers/anthropic/provider.ts:900,953` — reads the
     `anthropic-billing-cost` response header.
   - `providers/bedrock/provider.ts:739-760` — calls `estimateCostUSD("bedrock")`.
   - `providers/openai/provider.ts:336-367` — a hard-coded price table with a
     made-up default for unknown models, ignoring cache tokens.
2. `response-processor.ts:258,308` writes that value to the row via
   `updateRequestUsage` (a `COALESCE` update).
3. `usage-collector.ts:864-880` then **always** recomputes
   `state.usage.costUsd = estimateCostUSD(model, …)` and the `handleEnd` INSERT
   writes it. The provider's number is gone.
4. `usage-collector.ts:915` feeds the collector's number to the per-API-key
   spend counter, which is what gets enforced.

So the provider's cost never reaches the row the dashboard reads or the
counter that enforces spend limits.

### What the target behaviour needs

- The provider's cost must reach the collector. The collector's start message
  is emitted before the response body is parsed
  (`response-handler.ts:294`), so the value has to arrive later — either on the
  `EndMessage` (`worker-messages.ts:104`) or through a small setter on the
  collector keyed by request id.
- The collector must estimate **only when no provider cost is present**.
- The spend counter and the row must both use the provider's value when there
  is one.
- `openai-compatible`: delete `calculateCost` rather than keep it as the
  fallback — the local catalogue estimate is a better fallback than a
  hard-coded table with a fake default.
- OpenRouter is a real source worth wiring: its body carries
  `usage.cost` (see `providers/src/utils/provider-serving.ts:18`). NanoGPT is
  not wired for cost today.
- Streaming: `anthropic-billing-cost` is a response header, so it is available
  for both streaming and non-streaming responses. The streaming branch
  (`response-processor.ts:237`) already has the `Response` to read it from.

### Suggested split

1. Carry a provider cost through to the collector (message field + "estimate
   only if absent"). Test with a fake provider that reports a cost.
2. Wire the providers that actually report one (anthropic header, OpenRouter
   body `usage.cost`).
3. Delete the OpenAI-compatible price table.
4. Check the spend counter and the dashboard's cost columns use the same value.

## Remaining findings (not in this session's scope)

### 2. Daily-spend alert counts a rolling 24 hours

`packages/http-api/src/services/alerts.ts:630-635`. `dayStart` comes from
`setHours(0,0,0,0)` on the server clock (UTC), so the window is the server's
calendar day, not the operator's. It also re-sums `requests` on every finished
request. Compute the window once in the configured time zone (the night-window
code has a zone helper) and cache the running total per window. No test covers
this path.

### 5. Bedrock profile name is not escaped in a regex

`packages/http-api/src/handlers/accounts.ts:4252-4289`. `profile` is only
length-checked. `a.*` matches any profile in `~/.aws/credentials`; a `:` breaks
the `bedrock:profile:region` format. Add a pattern (`^[A-Za-z0-9._-]+$`) and
escape the regex input. Admin-only, so this is correctness, not an attack path.

### 6. `retry.ts` has no test

`packages/database/src/retry.ts` backs every database call. One test: a fake
operation failing with `SQLITE_BUSY` twice then succeeding, and one
non-retryable error failing immediately.

### 7. Async DB writer drops are invisible

`packages/database/src/async-writer.ts:93-110`. Under backpressure, request
rows and payloads are dropped with only a `warn` log. Surface
`metadataDropped` / `payloadDropped` in the health payload so `/health` and the
dashboard can show it.

### 9. Two ~5,000-line files mix unrelated jobs

`packages/http-api/src/handlers/accounts.ts` (5,089 lines) and
`packages/proxy/src/handlers/proxy-operations.ts` (4,756 lines). Split by job,
as separate mechanical moves.

### 10. `date-fns` could go

`packages/dashboard-web/package.json:35`. Seven dashboard files use `format`
or `formatDistanceToNow`. `ui-common` already has `formatTimestamp`; relative
times are a few lines with `Intl.RelativeTimeFormat`.

### 11. Cleanup endpoint re-sums every payload on each click

`database-operations.ts:1805`, `maintenance.ts:26`. The 60 s cache is cleared
by the cleanup itself right before the counts are read, so every click pays a
full `SUM(LENGTH(payload))` over the payload table.

### 13. Usage fetchers hand-copy the timeout pattern

`packages/providers/src/opencode-go-usage-fetcher.ts:94` and its siblings.
One shared `fetchWithTimeout` helper.
